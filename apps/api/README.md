# Серверный API

Собственный сервер на Python + FastAPI. Исходный код размещён в `app/`.

Сервер отвечает за логику приложения и интеграцию с поставщиком eSIM.
Секретный партнёрский токен используется только здесь.

## Запуск

Из корня репозитория (Python 3.12 или новее):

```bash
python3 -m venv apps/api/.venv
apps/api/.venv/bin/python -m pip install -r apps/api/requirements.lock
apps/api/.venv/bin/python -m pip install --no-deps -e apps/api
npm run api
```

Перед запуском создайте корневой `.env` из `.env.example`, если он ещё не создан.
Заполните `ESIM_PARTNER_TOKEN` партнёрским ключом `sk_live_…` и
`ESIM_PUBLISHABLE_KEY` публичным ключом `pk_live_…`. Этот файл не
попадает в Git и не используется мобильным клиентом. После изменения `.env`
перезапустите сервер.

По умолчанию пример `.env` задаёт `API_HOST=0.0.0.0`, чтобы сервер был доступен
телефону в той же локальной сети. Браузер приложения разрешён через
`API_CORS_ORIGINS`. Для другого адреса браузера добавьте его origin в этот список.

## Маршруты

- `GET /health` — состояние сервера и факт настройки каталога без значения токена.
- `GET /api/catalog/categories` — категории и страны SDK-каталога поставщика.
- `GET /api/catalog/esims/{esim_id}/tariffs` — тарифы выбранного направления
  из SDK; параметр должен быть UUID из каталога.
- `POST /api/checkout/summary` — расчёт тарифа; после входа возвращает серверный `quote_id`.
- `POST /api/orders` — принимает только `quote_id`, создаёт заказ и возвращает ссылку кассы.
- `GET /api/orders` — покупки текущего аккаунта с пагинацией.
- `GET /api/orders/{id}` — состояние платежа и данные установки выданной eSIM.
- `GET /api/orders/{id}/qr` — приватный файл QR для сохранения/отправки, только после выдачи и оплаты.
- `/docs` — Swagger собственного приложения; `/openapi.json` — контракт API.

Сервер выпускает ClientToken через `POST /v1/partner/client-tokens` с партнёрским
Bearer и UUID в `Idempotency-Key`, затем вызывает `GET /v1/sdk/esims`
с ClientToken в Bearer и `X-Publishable-Key`. Токен хранится в памяти процесса,
переиспользуется и обновляется перед истечением; при ошибке истечения SDK
чтение повторяется один раз с новым токеном. Одновременные обращения разделяют выпуск.

SDK-поля `items`, `country`, `name` преобразуются в `esims`, `country_iso2`,
`display_name`, чтобы сохранить контракт мобильного приложения.
Возвращаются поля собственного контракта: `title`, `esims`, `id`, `country_iso2`,
`display_name`, `image_url`, `min_price_amount`, `min_price_currency` и метаданные
пагинации, если они есть. Минимальная цена и валюта передаются без пересчёта.
Ошибки и неизвестные поля поставщика не пересылаются клиенту.

Тарифы загружаются через `GET /v1/sdk/esims/{id}/tariffs` с той же серверной
сессией чтения. В контракт входят страна, ID и название тарифа, объём, срок,
цена/валюта, флаг выгодного предложения и нормализованный признак безлимита.
Несовпадение ID страны в ответе считается ошибкой поставщика. Схема тарифов —
`packages/shared/contracts/tariffs.schema.json`.

При отсутствии любого из двух ключей сервер возвращает 503, при таймауте — 504,
при отказе доступа поставщика, некорректном ответе или другой ошибке — 502.
Маршрут чтения каталога доступен приложению без партнёрского ключа.

Выбор базы данных ещё не подтверждён; для чтения категорий база не требуется.
`ESIM_CATALOG_EXTERNAL_USER_ID` (по умолчанию `tursim-catalog`) задаёт служебную
идентичность только для каталога. Покупки используют отдельные пользовательские
SDK-сессии `tursim-user:<UUID аккаунта>`. Ключи и ClientToken клиенту не возвращаются.
Котировки, ключи повторов и принадлежность заказов сохраняются локально в SQLite;
файл `ORDERS_DATABASE_PATH` необходимо сохранять между перезапусками.
Настройки кассы, ограничения, сценарий и проверки: [checkout.md](../../docs/checkout.md).

## Проверка и контракты

```bash
npm run test:api
npm run contracts
```

Контракты экспортируются в `packages/shared/contracts`. При изменении моделей
обновляйте JSON Schema, OpenAPI, TypeScript-типы и клиентский код согласованно.
`requirements.lock` фиксирует проверенные версии, включая зависимости тестов.

Детали интеграции и результаты проверки: [catalog-api.md](../../docs/catalog-api.md).

## Вход по коду из письма

Добавлены маршруты /api/auth/email/send-code, /api/auth/email/verify,
/api/auth/refresh, /api/auth/logout и GET /api/me. SQLite используется только
для локальной проверки, SMTP настраивается серверными переменными окружения.
Подробности и команды Windows: [email-auth.md](../../docs/email-auth.md).
