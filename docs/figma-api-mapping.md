# ТурСим: сопоставление экранов Figma и API

Дата анализа: 8 октября 2026 года.

Обновление 15 октября: страны и категории уже читаются через `GET /v1/sdk/esims`
с автоматическим получением ClientToken на собственном сервере. Проверены
группы `data[].title`, элементы `items` с `id`, `country`, `name`, `image_url`,
а также наличие `phone_code`, `photo_url`, `min_price_amount`, `min_price_currency`.
Минимальные цены подключены: `min_price_amount` отображается напрямую с
`min_price_currency` (`199 RUB` → «от 199 ₽»). Пользовательские заказы пока не проверены.
Подробности: [SDK-интеграция](sdk-integration.md).

Экран «Страна · тарифы» (`64:3926`) реализован с данными
`GET /v1/sdk/esims/{id}/tariffs`: сроки, объёмы, цены, флаг выгодного предложения,
безлимит и выбор пакета. [Контракт и проверки](tariffs-api.md).

Экран «Регион · Европа» (`91:5136`) реализован для категорий с SDK-тарифами
регионального пакета и списком стран категории. Точное покрытие eSIM в этих
ответах не найдено; список категории не выдаётся за подтверждённое покрытие.
[Поведение и проверки](regions-api.md).

Раздел «Весь мир» (`103:49480`) реализован внутри экрана направлений: зелёная
карточка выбирает этот переключатель, тарифы приходят для SDK-пакета `XG`,
нижний таб-бар сохраняется. [Описание и проверки](world-screen.md).

## Результат

Каталог и создание заказов покрыты маршрутами. Для полного приложения из Figma не видно API входа по почте, копилки, докупки трафика и поддержки. Оплата и установка eSIM покрыты лишь частично: необходимо проверить контракты существующих маршрутов.

## Существующие маршруты и экраны

| Экран / функция | Маршруты на скриншоте | Покрытие и вопросы |
|---|---|---|
| Главная, все страны | `GET /v1/public/esims`; авторизованный аналог `GET /v1/sdk/esims` | Список групп eSIM есть. Нужно проверить наличие страны, названия, флага и минимальной цены. Популярные направления и рекламные блоки отдельно не видны. |
| Поиск страны или региона | Те же маршруты каталога | Можно искать по загруженному списку. Серверные параметры поиска на скриншоте не раскрыты. |
| Регионы, весь мир | `GET /v1/sdk/esims`; `GET /v1/sdk/esims/{id}/tariffs` | Категории, региональные и глобальные тарифы подключены. Пакеты исключаются из списка стран; точное покрытие требует данных поставщика. |
| Страна, тарифы, безлимит | `GET /v1/public/esims/{id}/tariffs`; `GET /v1/sdk/esims/{id}/tariffs` | SDK-тарифы подключены к экрану страны. В проверенных ответах нет сетей и 5G; правила активации, раздача интернета и ограничения безлимита ещё требуют проверки. |
| Срок поездки, объём интернета, подбор | Каталог тарифов | Выбор срока и простой расчёт можно выполнить в приложении. Отдельного API персонального/ИИ-подбора не видно. |
| Оформление заказа — экран 1.2 | `POST /v1/sdk/orders/summary`; `POST /v1/sdk/orders` | Есть расчёт корзины и создание заказа. Поддержка почты гостя, промокода и списания МБ неизвестна. |
| Ожидание оплаты, ошибка, повтор — экраны 1.3–1.4 | `GET /v1/sdk/orders/{id}` | Возможно получение статуса через заказ. Отдельных маршрутов запуска, повтора и отмены оплаты eSIM не видно. Платёжная ссылка может возвращаться при создании заказа. |
| eSIM куплена — экран 1.5 | `GET /v1/sdk/orders/{id}`; `POST /v1/partner/esims`; `GET /v1/partner/esims/{id}` | Есть выпуск eSIM и получение её деталей/расхода через Partner API. Связь оплаченного заказа с выпуском нужно уточнить. |
| Установка: быстро, QR, вручную — экраны 1.6–1.8 | Возможный источник: детали заказа или `GET /v1/partner/esims/{id}` | Не подтверждено наличие QR/LPA, SM-DP+ адреса, кода активации и ссылки быстрой установки. Отдельный маршрут необязателен, если эти данные уже возвращаются. |
| Мои eSIM, детали, остаток — экраны 2.1–2.3 | `GET /v1/sdk/orders`; `GET /v1/sdk/orders/{id}`; `GET /v1/partner/esims/{id}` | Частично: список заказов есть, детали и usage есть в Partner API. Нужно проверить получение списка выданных eSIM, срока действия и статуса каждой. |
| Докупить трафик — экран 2.4 | Явного маршрута нет | Создание нового заказа само по себе не подтверждает пополнение существующей eSIM. |
| История покупок и чеки | `GET /v1/sdk/orders`; `GET /v1/sdk/orders/{id}` | История заказов есть. Ссылки на чеки и возвраты не подтверждены. |
| Удалить аккаунт — экран 4.6 | `DELETE /v1/partner/users` | Есть анонимизация пользователя через сервер. Нужно определить судьбу активных eSIM, копилки и профиля приложения. |

Partner API вызывается с собственного сервера, например для выпуска eSIM, получения usage и удаления пользователя. Приложение может использовать Public/SDK API и собственные серверные маршруты. Секретный PartnerToken хранится на сервере.

## Возможности, которых не видно

Названия маршрутов ниже — предложения для собственного API. Это не существующие маршруты поставщика и не утверждённый контракт.

| Экраны Figma | Что необходимо добавить или подтвердить | Примеры маршрутов |
|---|---|---|
| Вход по почте → код — 4.2–4.3; оформление гостем | Отправка и проверка кода, сессия, привязка покупок к аккаунту | `POST /auth/email/send-code`, `POST /auth/email/verify`, `POST /auth/refresh` |
| Профиль — 4.4 | Имя, почта, настройки, выход | `GET /me`, `PATCH /me`, `POST /auth/logout` |
| Копилка → бонус дня забран | Баланс МБ, серия посещений, начисления, защита от повторного получения | `GET /loyalty`, `POST /loyalty/daily-claim`, `GET /loyalty/history` |
| Задания, поездки, уведомления | Список заданий, подтверждение выполнения, сохранение поездки и push-токена | `GET /loyalty/tasks`, `POST /trips`, `PUT /me/push-token` |
| Бесплатная eSIM за копилку; +340 МБ к покупке | Допустимые страны, лимиты, списание баланса и выдача награды | `GET /loyalty/rewards`, `POST /loyalty/redeem` |
| Паспорт | Посещённые страны, штампы, уровень, кешбэк | `GET /passport` |
| Пригласить друга | Код/ссылка, статистика, начисление после первой покупки друга | `GET /referrals`; начисление по событию покупки |
| Промокод: ввод → ошибка → применён — 3.4–3.6 | Проверка кода и серверный перерасчёт суммы | Возможно расширение `POST /v1/sdk/orders/summary`; иначе собственный маршрут |
| Докупить трафик — 2.4 | Доступные пакеты для конкретной eSIM, продление срока и пополнение без переустановки | `GET /esims/{id}/topup-options`, `POST /esims/{id}/topups` |
| Удалить eSIM из списка — 2.5 | Скрытие/архивирование либо отключение у поставщика: нужно определить поведение | Например, `PATCH /esims/{id}` с признаком архива |
| Поддержка — 4.5; запрос возврата | Диалоги, сообщения, обработка возвратов | `GET/POST /support/conversations`, `POST /orders/{id}/refund-request` |

Маршруты поддержки могут быть заменены интеграцией с внешней системой поддержки. Статические инструкции, документы, действия «скопировать», «поделиться», «сохранить QR» и выбор срока не требуют отдельного серверного маршрута сами по себе.

## Маршруты, которые нельзя автоматически считать покрытием приложения

- `/v1/public/goods/*` и `/v1/sdk/goods/orders/*` описаны как товары. Их нельзя считать маршрутами покупки eSIM без подтверждения модели данных.
- `POST /v1/admin/goods-orders/{id}/confirm-payment` — административное подтверждение оплаты товаров.
- `POST /v1/admin/provider-plans/{id}/issue` — административный выпуск eSIM без оплаты; это не готовая реализация награды из копилки.
- `/v1/partner/client-tokens/*` — техническая выдача и отзыв SDK-токенов, а не пользовательский вход по коду из письма.

## Вопросы поставщику перед подключением покупки

1. Что возвращает `POST /v1/sdk/orders` для оплаты: ссылка, QR СБП, идентификатор платежа? Какие способы оплаты доступны?
2. Какие статусы возвращает `GET /v1/sdk/orders/{id}`? Как повторить или отменить оплату? Есть ли уведомления о смене статуса?
3. Выпускается ли eSIM автоматически после оплаты или нужен отдельный вызов? Как исключить повторный выпуск при повторе запроса?
4. Где возвращаются QR/LPA, SM-DP+ адрес, код активации и ссылка быстрой установки?
5. Как получить список eSIM пользователя, остаток трафика, дату активации, дату истечения и актуальный статус?
6. Можно ли докупать пакет на тот же профиль, продлевать срок и подключать другую страну без переустановки? Какие ограничения у провайдеров?
7. Поддерживает ли `orders/summary` промокоды, дополнительные МБ и бонусы? Как итоговая сумма фиксируется при создании заказа?
8. Какие поля каталога доступны для регионов, покрываемых стран, сетей, 5G, правил активации и ограничений безлимита?
9. Как получить чек и оформить возврат? Что означает удаление/анонимизация пользователя для активных eSIM?

## Следующие шаги

1. Получить экспорт полной спецификации Swagger с моделями запросов и ответов.
2. Уточнить у поставщика оплату, выпуск, данные установки, usage и пополнение существующего профиля.
3. Зафиксировать контракт приложения и собственного сервера для аккаунта, копилки, паспорта, рефералов и поддержки.
4. Обновить этот документ после проверки спецификации: отделить подтверждённые возможности от предположений.
