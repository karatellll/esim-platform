# Вход по коду из письма

Реализованы собственные API и экраны почты/кода. Это локальная тестовая реализация:
SMTP отправляет настоящие письма, аккаунты и сессии сохраняются в SQLite.
Выбор базы данных для развёртывания проекта пока не утверждён.

## Настройка

Сервер читает корневой файл .env. Пример для Gmail:

    SMTP_HOST=smtp.gmail.com
    SMTP_PORT=465
    SMTP_USE_SSL=true
    SMTP_USERNAME=your-address@gmail.com
    SMTP_PASSWORD=
    MAIL_FROM="ТурСим <your-address@gmail.com>"
    AUTH_OTP_SECRET=
    AUTH_OTP_TTL_SECONDS=300
    AUTH_COOKIE_SECURE=false

SMTP_PASSWORD — пароль приложения Google, а не основной пароль аккаунта.
У Google должна быть включена двухэтапная аутентификация. Отправитель должен
совпадать с авторизованным почтовым ящиком. Для порта 587 требуется
SMTP_USE_SSL=false: сервер обязательно выполняет STARTTLS перед авторизацией.
Проверка сертификата не отключается. Основные инструкции:
https://support.google.com/accounts/answer/185833?hl=ru
https://developers.google.com/workspace/gmail/imap/imap-smtp

AUTH_OTP_SECRET должен содержать не менее 32 случайных символов и оставаться
постоянным между перезапусками. При настройке локального проекта он сгенерирован
в .env; его значение в документацию и Git не попадает. Ручная генерация:

    python -c "import secrets; print(secrets.token_hex(32))"

Путь по умолчанию: apps/api/var/auth.sqlite3. Его можно переопределить абсолютным
AUTH_DATABASE_PATH. В каталоге находятся также служебные файлы SQLite WAL;
каталог целиком исключён из Git. Не хранить эту базу на общем сетевом диске.

Для сохранения сессии на телефоне установить совместимый модуль:

    npm install --prefix apps/mobile expo-secure-store@~57.0.4

## API

| Маршрут | Запрос и результат |
| --- | --- |
| POST /api/auth/email/send-code | email; возвращает challenge_id, email, expires_in, resend_after_seconds |
| POST /api/auth/email/verify | challenge_id, code, client (web/native); возвращает подтверждённого пользователя и сессию |
| POST /api/auth/refresh | client; native также передаёт refresh_token, web использует HttpOnly cookie |
| POST /api/auth/logout | тот же формат; отзывает сессию и удаляет cookie, ответ 204 |
| GET /api/me | Authorization: Bearer access_token; возвращает текущего пользователя |

Запрос send-code одинаков для нового и существующего аккаунта. Аккаунт создаётся
только после успешной проверки кода. Адрес проверяется сервером; пробелы по краям
убираются, домен приводится к IDNA и нижнему регистру. Регистр локальной части
сохраняется: преобразований Gmail (удаление точек или +меток) нет. В ограничениях
отправки и попыток регистр адреса не различается.

Шестизначный код генерируется secrets.randbelow и действует 5 минут по умолчанию.
В базе хранится HMAC-SHA256 от кода, адреса и ID подтверждения. После использования,
успешной повторной отправки или ошибки доставки значение HMAC очищается.
Сетевой таймаут SMTP может означать, что письмо всё же было принято: в этом случае
сервер сообщает об ошибке, код для неуспешного запроса не принимается; новый запрос
доступен после задержки. SMTP не гарантирует идемпотентную доставку.

Ограничения хранятся в SQLite и переживают перезапуск процесса:

- Повторная отправка на адрес — через 60 секунд, не более 6 отправок в час.
- На IP — не более 20 отправок в час. Неудачная доставка тоже учитывается.
- Не более 5 неверных проверок одного кода.
- Не более 10 проверок на адрес за час, включая новые коды и успешные входы.
- На IP — не более 60 проверок за 5 минут.

Погашение кода и создание аккаунта/сессии выполняются в одной транзакции:
один код не может создать две сессии при одновременных запросах.
API не возвращает код, пароль SMTP, HMAC или внутреннюю ошибку почтового сервиса.
Ошибки валидации авторизации не отражают введённые коды в ответе.

Access-токен действует 15 минут и находится в памяти приложения. Refresh-токен
действует до 30 дней с момента входа; обновление не продлевает этот срок.
При каждом refresh оба токена заменяются, предыдущие становятся недействительны.
В базе хранятся только SHA256-хеши случайных токенов. После выхода сессия отзывается.
На iOS/Android refresh-токен хранится в Expo SecureStore (ThisDeviceOnly на iOS),
в браузере — в HttpOnly/SameSite=Lax cookie с путём /api/auth. localStorage не используется.

Браузерные запросы verify/refresh/logout требуют Origin из API_CORS_ORIGINS;
для cookie включён CORS с credentials. Для удалённого браузерного адреса нужно
добавить его точный origin в конфигурацию и использовать HTTPS.
AUTH_COOKIE_SECURE=true обязателен при развёртывании с HTTPS.
Прокси должен передавать корректную информацию о клиентском IP через доверенную
конфигурацию Uvicorn; приложение само не доверяет произвольному X-Forwarded-For.

## Интерфейс

Источники Figma: вход 91:5752, код 91:5776 в MVP 64:3348.
Экспортированы оригинальные SVG back/email-sticker/code-sticker в assets/auth.
SVG-экспорт включает исходный поворот стикеров; дополнительного поворота картинки нет.
Статус-бар, клавиатура и системная полоса жестов в коде интерфейса не рисуются.

Кнопка профиля открывает почту, после отправки — код с шестью ячейками.
Поддерживаются вставка, автозаполнение, автоматическая проверка шестой цифры,
ошибки, таймер повторной отправки, истечение кода и исправление почты.
После входа открывается исходная вкладка, профиль показывает подтверждённую
почту и выход. На вкладке копилки доступна та же точка входа. Баланс и начисления
копилки не подключены и не изображаются как готовые данные.

SDK поставщика по-прежнему используется только для каталога. Этот вход не
создаёт заказы, не объединяет гостевые покупки и не выпускает пользовательский
ClientToken поставщика. Это отдельные последующие интеграции.

## Запуск и проверки в Windows PowerShell

Из корня репозитория:

    powershell -ExecutionPolicy Bypass -File scripts/check-auth.ps1

Скрипт устанавливает SecureStore при необходимости, выполняет тесты API,
экспортирует контракты и проверяет TypeScript. Лог: ../.run/auth-check.log.
Тесты используют временные базы и подмену SMTP; настоящие письма не отправляются.
Проверяются одноразовость и конкурентное погашение кода, срок, лимиты, повторная
отправка, ошибка SMTP, ротация, выход, восстановление после перезапуска и CORS/Origin.

Запуск API отдельной командой без установки editable-пакета:

    apps/api/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir apps/api --host 0.0.0.0 --port 8000 --reload

Клиент:

    npm run web

Ручная проверка доставки: Профиль → Войти по почте → ваш адрес → Получить код.
Проверить письмо, ввести код, обновить страницу и выйти. Автоматические проверки
не подтверждают доставку в реальный ящик. Перед публичным запуском нужны
выбранная production-база, TLS, защищённый reverse proxy, наблюдение за доставкой
и дополнительная защита от распределённого перебора и массовой отправки писем.
