# ТурСим: контекст проекта

Пользователь хочет начать разработку приложения для iOS и Android по своему
готовому дизайну Figma. Интерфейс и интеграцию с поставщиком eSIM нужно вести
параллельно, согласовав контракт между ними.

## Технологии

- Пользователь выбрал Python + FastAPI для собственного бэкенда.
- 13 октября пользователь выбрал React Native. Мобильное приложение
  инициализировано на Expo + TypeScript с навигацией React Navigation.
- PostgreSQL предложена для базы данных; выбор ещё не подтверждён.
- В приложении созданы таб-бар по Figma и пять маршрутов. Во вкладке «Страны»
  добавлены заголовок, поиск, переключатели и карточка глобальной eSIM;
  остальные экраны пустые. Сервер получает страны и категории через SDK API
  (`GET /v1/sdk/esims`) с автоматическим выпуском и обновлением ClientToken,
  приложение отображает уникальные страны по алфавиту с поиском и боковым
  указателем букв, а категории — карточками в разделе «Регионы».
  Минимальные цены стран и категорий подключены к денежным полям SDK;
  цена глобального пакета загружается из записи `XG` вместо значения макета.
  Карточка глобального пакета переключает раздел на «Весь мир», реализованный
  по Figma `103:49480`, с тарифами XG и видимым нижним таб-баром.
  Из списка стран открывается экран тарифов по Figma `64:3926`; сроки,
  пакеты и итоговая цена подключены к `GET /v1/sdk/esims/{id}/tariffs`.
  Карточки категорий открывают экран региона по Figma `91:5136` с чипами стран
  и тарифами соответствующей региональной eSIM; без пакета доступен выбор страны.
  Детали: [mobile-navigation.md](mobile-navigation.md).

## Поставщик eSIM

- Админка: https://esim-api.terexov-tech.ru/admin
- Swagger: https://esim-api.terexov-tech.ru/swagger/
- Документация: https://esim-api.terexov-tech.ru/swagger/doc.json
- Роль пользователя в админке: tenant_admin.
- В документации Swagger 2.0 указан host localhost:8080 и basePath /.
  Поэтому Try it out обращается к компьютеру пользователя.
- По скриншоту Postman GET /v1/partner/catalog/categories на внешнем домене
  8 октября вернул 200 с data: [] и meta.has_more: false.
- 13 октября проверен живой запрос через собственный FastAPI: категории
  возвращают 200, 7 групп и 160 записей eSIM, meta.has_more=false.
  Секретный токен установлен в локальном `.env`, в документации его нет.
- GET /v1/partner/catalog на том же домене вернул 404 с code: not_found.
  Причина не установлена. Поставщик сообщил, что заполнит тарифы позже;
  причинная связь между отсутствием тарифов и 404 не подтверждена.
- Полный swagger.json ещё не сохранён в проекте.
- Попытка загрузки `/swagger/doc.json` 8 октября 2026 года вернула HTTP 401.
  Сопоставление выполнено по списку маршрутов на скриншоте; модели запросов
  и ответов не проверены.

## Авторизация

- PartnerToken: секретный sk_live_… в Authorization: Bearer <token>.
- PublishableKey: публичный pk_live_… в X-Publishable-Key.
- ClientToken: клиентский токен SDK в Authorization: Bearer <token>.
- AdminSession: cookie admin_session.
- Секретный партнёрский токен должен храниться на собственном сервере.
  Ранее токен попал на скриншот; пользователю рекомендована его замена.
  Секреты в этом файле отсутствуют.

## Переход на SDK

13 октября пользователь сообщил о подключении к кассе партнёра и выбрал
SDK-методы для приложения. Настройки ключей, выпуск и обновление ClientToken,
проверенные запросы Postman и оставшиеся задачи записаны в
[sdk-integration.md](sdk-integration.md). Реализация отложена по просьбе пользователя.
15 октября реализовано чтение каталога через `GET /v1/sdk/esims`.
Сервер читает `ESIM_PUBLISHABLE_KEY`, выпускает ClientToken для отдельной
служебной идентичности каталога, переиспользует его и обновляет перед истечением
или один раз после отказа SDK. Проверен живой запрос через FastAPI: HTTP 200,
7 категорий, 160 записей, 147 уникальных стран без региональных пакетов.
Покупки и пользовательские SDK-сессии ещё не реализованы.
