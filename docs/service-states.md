# Ошибки и служебные экраны

Состояния реализованы по разделу Figma [«Ошибки и служебные экраны»](https://www.figma.com/design/PWdKnO2WHAIS0NE18vlgL4/?node-id=258-10350).

| Состояние | Когда появляется |
|---|---|
| Нет интернета при запуске | Устройство открывает приложение без сети. «Мои eSIM» открывает ранее сохранённые покупки. Экран закрывается при восстановлении связи. |
| Нет сети внутри приложения | Текущий экран и уже загруженные данные остаются на месте. Сетевые действия блокируются до восстановления связи. |
| Ошибка сервера | При недоступности API на старте или ответе 500/502 при первой загрузке главной. Доступны повтор и поддержка. |
| Технические работы | Ответ 503 от `GET /api/app-status`. Если передано время окончания, оно показывается по Москве. |
| Обязательное обновление | Ответ 426 от `GET /api/app-status`. Экран предлагает открыть магазин для текущей платформы. |
| Страница не найдена | Неизвестный путь, удалённое направление или заказ. |
| Сессия истекла | Подтверждённый 401 при обновлении существующего входа. После ввода кода открывается прежний экран. |
| Не загрузились страны, тарифы, eSIM или копилка | Сохраняется контекст экрана. Ошибка показывается после сбоя или 10 секунд ожидания. «Повторить» выполняет тот же запрос. |
| Цена не подтвердилась | Сбой расчёта, устаревшая котировка или изменение цены до создания заказа. Повтор обновляет расчёт. Неопределённый результат уже запущенной покупки сохраняет прежнюю котировку и исходный ключ идемпотентности. |
| Копилка гостя и пустая копилка | Гостю показана выгода и вход по почте. Для вошедшего пользователя с подтверждённым пустым списком заказов показывается 0 ₽ и переход к выбору eSIM. История отсутствует в обоих состояниях. |

## Сервер

Публичный `GET /api/app-status?platform=ios&version=0.1.0` проверяется при открытии, возврате из фона и каждые 30 секунд при наличии сети. Для технических работ задайте `APP_MAINTENANCE=true` и при наличии срока `APP_MAINTENANCE_UNTIL` как ISO 8601 с часовым поясом. После указанного времени статус возвращается к 200.

Для обязательного обновления задайте `APP_MINIMUM_IOS_VERSION` и `APP_IOS_STORE_URL` или `APP_MINIMUM_ANDROID_VERSION` и `APP_ANDROID_STORE_URL`. Требуется HTTPS-ссылка магазина. Настройки по умолчанию разрешают запуск. `/health` остаётся проверкой работоспособности API.

Авторизованный `GET /api/me/savings` подтверждает пустую копилку через реальный список заказов. При наличии заказов API отвечает `503 savings_unavailable`, пока доступ к денежному балансу и истории поставщика не подтверждён.

## Сохранённые покупки

На iOS и Android сведения о ранее загруженных выданных eSIM и доступные QR сохраняются в закрытом кэше приложения. Кэш привязан к последнему аккаунту на устройстве и очищается при явном выходе. QR и ручные реквизиты доступны офлайн после первой успешной загрузки данных установки. ОС может очистить кэш. В браузере список и ручные реквизиты сохраняются только в памяти открытой вкладки.

`npm run typecheck` и `npm run test:catalog` выполняются из `apps/mobile`. Серверные проверки запускаются из `apps/api` командой `.venv/bin/python -m pytest`.
