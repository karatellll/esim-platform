# Поиск 2.0

Источник: секция `64:3348` в файле ТурСим,
фреймы `208:7665` (первая страна), `208:6887` (маршрут),
`208:7231` (несколько вариантов использования интернета).

Шторки реализованы в `apps/mobile/src/components/HomeSearchSheet.tsx`.
Оригинальные SVG находятся в `apps/mobile/assets/search`; размеры изображений
сохранены: глаза 32×20, иконки полей 22×22, удаление 12×12,
закрытие 14×14, выбор страны 18×18, выбор назначения 16×16.
Клавиатура системная, выбранные страны остаются внутри поля.
Кнопка очистки сбрасывает все страны, удаление чипа — одну страну.
После выбора можно вернуться к любому полю, закрыть и снова открыть подбор.

Поиск получает страны из существующего `GET /api/catalog/categories`.
Для маршрута выбирается наименьшая категория с региональным пакетом,
содержащая все выбранные страны. Состав категории не доказывает покрытие:
перед покупкой это явно обозначено. Сравнение минимальных цен допускается
только в одной валюте; подпись «выгоднее» зависит от реальных цен.
При выборе отдельных eSIM на последнем шаге доступны тарифы каждой страны.

Оценка расхода локальная: выбранные назначения суммируются (0,5 / 0,5 / 2 /
5 / 2 / 5 ГБ в неделю), добавляется 1 ГБ запаса. Для варианта «2 недели»
расход оценивается за 14 дней, срок тарифа требуется от 15 дней. Для других
сроков учитывается полная длительность. При пропуске срока и выборе расхода
используется оценка на две недели. Рекомендация — реальный самый дешёвый
пакет, удовлетворяющий обоим ограничениям; сравнения разных валют нет.
В карточке показаны фактический объём, срок и цена пакета.
Предпочтения передаются как в CountryTariffs, так и в RegionTariffs,
чтобы открывался именно рекомендованный тариф. При отсутствии совпадения
показано пояснение и доступны существующие тарифы.

Операторы и 5G из макета не подставляются: контракт каталога этих данных
не содержит. Под странами показаны реальные минимальные цены. Числа
из макета (33 страны, 490/870/1490 ₽) не выдаются за данные API.
API и база данных не менялись: предпочтения подбора хранятся в состоянии
экрана до перезапуска приложения.

## UX-сценарии умного поиска, 30 октября 2026

Источник: `246:10922`, «UX-сценарии · умный поиск». Новые правила заменяют
предыдущий выбор наименьшей категории и безусловный показ отдельных eSIM.

- Одна доступная страна → её тарифы; общий регион → одна региональная eSIM
  независимо от цены отдельных. При пересечении категорий выбирается общая
  категория, при равном числе стран — меньшая известная цена в одной валюте.
- Смешанный маршрут → XG («Весь мир»). Комплекты перебираются полностью
  для маршрута до пяти стран, включая регион + отдельные страны. Более
  дешёвый комплект показан второй строкой; более дорогой — одной фразой.
  Сравнение учитывает загруженные реальные тарифы и выбранные параметры;
  неизвестные цены и разные валюты не сравниваются.
- Лимит пяти стран проверяется и в интерфейсе, и в функции изменения выбора.
  На пятой стране ввод/добавление блокируются; удаление остаётся доступным.
  С четырёх стран общего региона доступна подсказка; работают переходы
  «Регионы»/«Весь мир» и выбор региона целиком без добавления всех его стран.
- В стопке максимум три кружка: до трёх флагов, либо два и «+N».
  Поиск понимает префиксы, одну опечатку/перестановку, другую раскладку,
  русские/английские названия ISO 3166-1, синонимы и распространённые города
  и курорты. Причина совпадения показана под страной. Неизвестный запрос
  отличается от известной страны, отсутствующей в каталоге.
- Россия исключается из подбора; отсутствующие страны остаются приглушёнными
  в маршруте, но не отправляются в API тарифов. По остальным странам подбор
  продолжается. При отсутствии отдельных тарифов предлагается XG, если он
  есть; точное покрытие SDK не возвращает, поэтому оно не заявляется как факт.
- При смене стран/срока/расхода пересчитываются пакет и сравнение. Расход
  свыше 25 ГБ предпочитает существующий безлимитный пакет. «Больше месяца»
  означает первоначальный пакет на 30 дней.
- Загрузка цен и ошибки не сбрасывают выбранные страны. До получения цены
  «Дальше» заблокирована, доступен повтор. Возврат интернета в браузере и
  возврат приложения на передний план повторяют чтение каталога.
- При наличии активной/установленной покупки этой страны показан переход
  в существующую eSIM и пояснение о текущем ограничении пополнения.

### Уведомления

Собственные маршруты (Bearer подтверждённого почтового аккаунта):

- `GET /api/me/coverage-subscriptions` — собственные заявки.
- `POST /api/me/coverage-subscriptions` — `{ "country_iso2": "KP" }`.
- `POST /api/me/coverage-subscriptions/cancel` — отмена по тому же коду.

Заявки сохраняются в таблице `coverage_subscriptions` существующей локальной
SQLite авторизации. Повторная заявка не создаёт дубль, другой аккаунт её не
видит. Гость проходит имеющийся вход по коду, после чего заявка сохраняется.
В интерфейсе можно отменить уведомление. Общий контракт —
`packages/shared/contracts/coverage.ts`, JSON Schema и OpenAPI экспортируются
командой `npm run contracts`.

Для реальной отправки нужен отдельный процесс с тем же серверным `.env`:

```bash
apps/api/.venv/bin/python -m app.coverage_worker --watch
```

Без `--watch` выполняется одна проверка (можно запускать по расписанию).
Процесс проверяет доступность каталога и непустых отдельных тарифов раз в час,
после чего отправляет одно письмо на подтверждённую почту пользователя через
те же SMTP-настройки. Он не запускается автоматически с `npm run api`.
В этой сессии отправка реальных писем и запуск worker не выполнялись.
При неопределённой ошибке SMTP заявка получает `failed` и не отправляется
повторно автоматически, чтобы не дублировать письмо; нужна сверка доставки.
Статус `sending` после аварийного завершения тоже требует ручной сверки.

### Ограничения подтверждённого SDK

Общая оплата комплекта, пополнение того же ICCID и продление существующего
профиля по имеющемуся Swagger не подтверждены. Поэтому в раскрытом комплекте
работает оформление отдельных eSIM, а общей оплаты нет. Для действующей
покупки открываются её данные; кнопки не выдают покупку новой eSIM за пополнение.
Автоматическое напоминание о продлении не обещается. Для завершения этих веток
нужны подтверждённые методы поставщика и интеграция оплаты нескольких пакетов.
