## Размеры и взаимодействие

Базовая ширина 375. Результат покупки: верхний отступ 64 с учётом верхней
безопасной области, горизонтальные отступы 12, расстояния блоков 16,
карточка со скруглением 28 и отступами 18, кольцо 150 × 150.
Нижние кнопки высотой 56 с промежутком 10, отступом сверху 12 и снизу 42 в web.
В нативном клиенте отступы учитывают safe area устройства.

«Установить eSIM» открывает шторку поверх результата, «Позже» возвращает
в «Мои eSIM». Шторка: 594 по высоте на экране 812, начинается с 218;
скругления 32, отступы 28/12/42 и промежутки 14. Переключатель высотой 44,
его кнопки 36. Шапка 40, закрытие 40 с исходной иконкой 20.
На коротком экране шторка уменьшается и прокручивается. Крестик, затемнение,
Escape в web и Back на Android закрывают установку.

Вкладка «Быстро»: исходная иллюстрация телефона 319 × 200, карточка 308,
кнопка лаймового цвета. На поддерживаемом iPhone кнопка открывает универсальную
ссылку Apple с полной LPA-строкой из оплаченного заказа. На других устройствах
предлагается QR. Поддержку ссылок начиная с iOS 17.4 описывает
[Apple](https://support.apple.com/en-ie/118669); форма universal link приведена
в [документации 1GLOBAL](https://docs.connect-api.1global.com/recipes/esim-installation).
Открытие установщика не меняет статус eSIM в приложении: он приходит от API.

Вкладка «QR-код»: белая рамка 204 × 204 с отступом 14, изображение 176 × 176,
две кнопки 56 с промежутком 8. Срок подписанного QR отслеживается существующим
опросом заказа; обновление данных не сбрасывает открытую вкладку.
QR не кешируется на диск приложением. Пользователь может явно скачать или
передать его через системное меню. В браузере без Web Share «Поделиться»
скачивает изображение с явной подписью. На iOS используется системное меню
для изображения; на Android передаётся актуальная подписанная ссылка, а
сохранение открывает изображение в браузере. Эти нативные действия на устройстве
ещё не проверялись.

Вкладка «Вручную»: исходные две строки с отдельными кнопками копирования,
SM-DP+ и Matching ID. Полная LPA-строка не выдаётся за ручной код активации.
При отсутствии структурированных полей они извлекаются из корректной LPA.
Копирование использует API браузера либо доступный Clipboard текущего RN 0.86.
Этот RN API помечен deprecated; отдельная новая зависимость не вводилась.
«Подробная инструкция» раскрывает инструкцию внутри шторки.

## Реальные данные

Результат показывается только для своего заказа с `state=delivered` и
`payment.state=captured`. Название страны, пакет, срок, сумма, остаток и статус
читаются из заказа. Пока remaining неизвестен, центр кольца описывает объём
купленного пакета, а легенда явно сообщает «Остаток уточняется»; неизвестный
остаток не превращается в ноль. При наблюдаемом usage кольцо показывает долю
остатка, включая честный ноль. Даты берутся из activated_at/expires_at.

SDK не возвращает сеть/5G, кешбэк или отправку чека на почту. В соответствующих
местах макета показаны реальные пакет/срок и оплаченная сумма/номер заказа;
совет про Wi-Fi ссылается на данные в приложении. Фиктивных Turkcell, +44 ₽ и
обещания отправленного письма нет.

## Приватный файл QR

Новый `GET /api/orders/{id}/qr` требует Bearer-сессию и проверяет владельца.
Он заново читает личный заказ и его актуальную подписанную ссылку, разрешает
скачивание только доставленному оплаченному заказу и возвращает PNG/JPEG/WebP
с `Cache-Control: no-store`, attachment и nosniff. Поставщику хранилища не
передаются SDK/партнёрские заголовки. Ограничение файла — 2 МБ; HTML/неизвестные
форматы отклоняются. Отменённый заказ не позволяет скачать прежний QR.
Это также позволяет скачать файл в web без зависимости от CORS хранилища QR.
OpenAPI и общий контракт обновлены.

Сервер должен перечитать код после изменения:

```powershell
& D:\esim\restart-api.ps1
```

## Проверка

Прошли TypeScript, 31 тест клиентской логики и все 105 серверных тестов,
включая 22 теста оформления, в том числе
проверки приватного QR, возврата, отсутствия утечки ключей и размера/формата
файла. Web-экспорт собран с 12 новыми непустыми оригинальными ресурсами.
Реальные заказы и платежи при проверке не создавались.

Визуальное превью для разработки: `http://localhost:8081/?visual=installation`.
Оно доступно только при __DEV__, явно помечено как тестовое, использует настоящие
компоненты интерфейса и не обращается к аккаунтам или API создания заказов.
Пример QR из макета расположен только в `apps/mobile/qa` и не используется
для установки реальной eSIM. В production-экспорте превью отключено.

Визуальная сверка работающих экранов не подтверждена: Computer Use остановил
управление Chrome, поскольку не смог надёжно определить адрес текущей вкладки.
После этого UI-ввод не выполнялся. Сверены исходные слоты, размеры SVG и их
применение в компонентах; пиксельное совпадение в браузере/на устройстве не заявляется.
